# KINEX — 骑行姿态运动学分析与追踪

KINEX 是一个基于 Python、OpenCV 与 Qt 的骑行姿态分析原型。项目围绕视频或相机中的反光标记点，提供人体关节追踪、二维关节角度计算、骑行运动指标统计，以及实时可视化界面。仓库还包含标记点关联与运动预测模块、骑行者几何模型和离线追踪评测脚本。

> **重要：结果是图像平面上的二维估计，不是医疗诊断，也不等同于真实三维生物力学测量。** 相机视角、透视、遮挡、标记点粘贴位置、视频质量及标定方式都会影响结果。请勿仅凭本程序输出做医疗或训练安全决策。

## 项目现状与运行说明

该仓库包含姿态分析相关 Python 源文件、演示视频、遮罩图片和 MediaPipe 模型文件，但目前没有 `requirements.txt`、完整的 `vision` / `core` / `capture` / `utils` 依赖包，也没有独立的安装配置。`app.py` 和部分模块通过 `pose_analysis.*` 及这些宿主项目包导入代码，因此**当前仓库并非开箱即用的独立应用**。运行 GUI 前，需要将本项目放入相应宿主工程的包结构中，并提供这些依赖；否则会遇到模块导入错误。

离线追踪评测脚本使用仓库中现有的 `tracking_engine.py` 和 `videos/demo.mp4`，不依赖 Qt 或 MediaPipe，可先用来检查基础追踪流程。

## 功能概览

- **反光点检测与身份关联**：通过亮度、形状、尺寸、对比度及局部区域搜索提取候选点，并依据预测位置和骨段长度约束，将候选分配给关节。
- **运动预测与丢失恢复**：使用带加速度状态的 α-β-γ 运动预测器平滑轨迹；结合标定位置和自适应搜索范围，在短暂遮挡或运动模糊时尝试保持追踪。
- **自动与手动标定**：自动标定根据人体几何布局和朝向估计 8 个关节点；GUI 还提供按指定顺序点击标记点的手动标定流程。
- **二维角度计算**：从腕、肘、肩、髋、膝、踝、脚跟和趾骨等位置计算肘、肩、髋、膝、踝角度，并可对超出配置范围的角度进行颜色提示。
- **骑行指标统计**：`metrics.py` 提供实时值、最大值、最小值和平均值等统计逻辑，涉及踏圈计数、关节角度、足膝偏移、KOPS、髋部位移及关节偏摆等指标。
- **骑行者几何模型**：`rider_model.py` 汇总左右侧数据；在只有单侧数据时，可基于踩踏相位估计另一条腿的姿态，并生成正面视图所需几何。
- **实时 GUI 与流水线**：`app.py` 实现视频/相机交互、参数调整、标定、指标面板和 HUD；`realtime_pipeline.py` 将采集、处理与 GUI 显示拆分到不同线程，降低界面阻塞。
- **离线追踪评测**：`eval_tracking.py` 可在示例视频上运行追踪关联，并统计命中数及输出位置与强反光点的偏离情况。

## 环境与依赖

建议使用 Python 3.9 或更新版本，并在虚拟环境中安装依赖。仓库没有锁定依赖版本，以下为源文件中可确认的主要第三方依赖：

- NumPy
- OpenCV（`opencv-python`）
- PyQt6（GUI）
- MediaPipe（MediaPipe 追踪路径）

安装基础图像处理依赖：

```bash
python -m venv .venv
# Windows PowerShell
.venv\Scripts\Activate.ps1
# macOS / Linux
source .venv/bin/activate

python -m pip install --upgrade pip
python -m pip install numpy opencv-python
```

使用 GUI 或 MediaPipe 追踪时，还需要安装对应依赖：

```bash
python -m pip install PyQt6 mediapipe
```

相机支持取决于宿主工程中的设备驱动模块和系统环境。Kinect v2 路径还需要相应的 Kinect SDK / Python 绑定；普通 USB 摄像头则依赖 OpenCV 或宿主项目的相机封装。请根据实际设备配置，不要假设所有相机都可直接使用。

## 运行方式

### 离线追踪评测

在仓库根目录执行：

```bash
python eval_tracking.py tracking_engine.py videos/demo.mp4
```

脚本会打印视频帧数、平均命中关节数和输出位置偏离强反光点的统计。评测脚本中的 `APPROX` 是为 `demo.mp4` 编写的近似首帧位置；换用其他视频时，需要先调整 `eval_tracking.py` 中的标定位置。该脚本是便于快速检查追踪器的轻量评测，不是完整的精度基准或临床验证。

### GUI 与视频分析

完成上文所述的宿主工程依赖和包结构集成后，可从宿主工程的适当位置启动 GUI。`app.py` 中包含 GUI 主入口，支持加载视频、自动/手动标定、播放控制和实时指标显示；具体启动命令取决于宿主工程如何组织 `pose_analysis`、`vision`、`core`、`capture` 和 `utils` 模块。

`main.py` 是另一份简化分析示例，同样导入宿主工程中的 `vision`、`core` 和 `capture` 模块。当前仓库根目录下直接执行 `python app.py` 或 `python main.py` 可能因上述模块缺失而失败。

## 使用流程（GUI 集成后）

1. 加载视频，或连接宿主工程已支持的相机设备。
2. 在相对清晰、标记点可见的画面上进行标定。
3. 自动标定后检查 1–8 编号与关节点对应关系；若误配，重置后改用手动标定。
4. 开始播放并观察追踪命中、角度、指标和丢失提示。
5. 按实际拍摄条件调整亮度、标记点半径、搜索范围、平滑参数和角度阈值。
6. 对关键分析结果使用经验证的测量工具或人工复核，不要将估算值直接视为精确测量。

## 配置提示

- GUI 的检测阈值、最小/最大半径、圆度、搜索区域、运动门限、平滑和角度范围由 `app.py` 中的 `AppConfig` 管理，并提供交互式调整控件。
- `main.py` 的简化演示参数位于文件开头；其默认 `DEMO_MODE = True` 使用合成红外画面。切换为真实视频时，需要设置 `VIDEO_PATH`，并确认宿主工程依赖可用。
- `metrics.py` 支持通过环境变量调整长度换算和踏轴点：`KINEX_THIGH_CM` 默认 `43`（设为 `0` 时不进行大腿长度厘米换算），`KINEX_SPINDLE` 默认 `8`，可设为 `6` 或 `7` 使用其他标记点作为踏轴近似。
- `pose_landmarker_full.task` 是 MediaPipe 模型资源。实际模型查找路径由宿主工程的 `resource_path` 决定；集成后应确认打包和运行时资源路径正确。
- 角度阈值是示例配置，不是适用于所有骑行者、器材或相机视角的医学标准，应依据使用场景校验和调整。

## 追踪与测量限制

1. **二维投影限制**：角度基于图像 X/Y 坐标。相机未垂直对准运动平面、骑行者存在侧向运动或透视明显时，投影角度会与三维真实角度不同。
2. **标记点依赖**：检测效果取决于反光点在图像中的可见度、大小、对比度、遮挡和粘贴位置；错误标定会影响后续的身份关联和所有衍生指标。
3. **模型估计不等于观测**：部分正面/对侧腿姿态和横向运动量可能通过模型模拟或相位模板估计。请结合输出来源和实际传感器数据解读。
4. **单位与标定**：长度指标由大腿像素长度及默认大腿长度换算，默认值是配置假设；没有可靠尺寸标定时，厘米数值不应视为精确值。
5. **设备差异**：视频帧率、分辨率、镜像方向、曝光和相机驱动都会改变追踪行为；真实设备应单独验证。

## 开发与扩展

- 追踪算法：从 `tracking_engine.py` 的 `MotionPredictor` 和 `MarkerAssociator` 入手。
- 标定策略：查看 `auto_calib.py` 的朝向判断与人体布局评分。
- 指标定义：查看 `metrics.py` 中的 `compute_all_metrics`、`MetricsCollector` 和 `BilateralMetrics`。
- GUI 与线程：查看 `app.py`、`realtime_pipeline.py`。
- 骑行者几何与视图：查看 `rider_model.py`、`xray_skeleton.py` 和 `front_knee_view.py`。
- 离线检查：使用 `eval_tracking.py`，并为不同视频更新初始标定位置。

提交改动时，建议同时说明测试视频、标定方式、运行环境和评测结果。仓库目前没有声明测试套件或持续集成流程，因此新增行为应至少通过合适的样例视频和目标设备进行人工验证。
